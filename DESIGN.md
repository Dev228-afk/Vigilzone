VigilZone Front-End Design System & Architecture1. Core Layout Paradigm: The App ShellVigilZone operates as a real-time surveillance dashboard. Standard web document layouts (where the <body> scrolls) are strictly prohibited. The application utilizes an Edge-to-Edge App Shell.Global Wrapper: The main application root is locked to h-[100dvh] w-full overflow-hidden flex flex-col.Navigation: Fixed height (e.g., h-16 flex-none).Content Area: Occupies remaining space (flex-1 w-full overflow-hidden).Grid System: Uses fluid CSS Grids (grid-cols-1 lg:grid-cols-12). Fixed width containers (.container mx-auto) are forbidden.Independent Scroll Zones: Data heavy panels (like the Incident Feed or Camera Grid) must handle their own scrolling (overflow-y-auto) so the user never loses sight of critical video feeds.2. Typography & Spacing SystemTypographyFont Family: Inter or system sans-serif (font-sans).Headings: tracking-tight font-semibold to maximize space efficiency.Data Labels: text-[10px] uppercase tracking-wide (Used for severity labels).Body: text-sm (Default for dashboard readability).Spacing & Margins (The 4-Point Grid)VigilZone relies on a tight 4-point/8-point spacing grid to pack data densely without feeling cluttered.Global App Padding: p-2 md:p-4.Grid Gaps: gap-4 between major panels; gap-2 between tightly related components (like badges).Card Inner Padding: p-4 for standard content, p-3 for dense list items (like notifications).Border Radius: rounded-xl for main outer panels, rounded-lg for inner cards/videos, rounded-full for badges.4. Component Implementation GuidelinesA. The Camera Feed (CameraFeed.tsx)Layout: Must use flex flex-col h-full w-full. Never use aspect-video on the container, as it leaves dead space in flexible grids.Video Element: The <video> or <iframe> tag must be absolute inset-0 w-full h-full object-contain bg-black.Overlays: Status badges must float using absolute top-2 left-2 z-10.Separation of Concerns: Visually separate the "Stream Health" badge (Live vs Offline) from the "AI Status" badge (Synced vs Unsynced).B. Cards & Panels (Card.tsx)Structure: Every panel must have a fixed header (flex-none border-b p-4) and a scrollable body (flex-1 overflow-y-auto p-4).Styling: bg-card border rounded-xl shadow-sm overflow-hidden text-card-foreground.Hover States: Interactive list items inside cards should use hover:bg-accent/70 transition-colors cursor-pointer.C. The Notification Bell (NotificationBell.tsx)Unread Counter: Absolute positioned top-[-4px] right-[-4px] with bg-destructive text-[10px] font-semibold text-destructive-foreground px-1 min-w-[20px] rounded-full.Dropdown: Must use max-h-[70vh] with <ScrollArea type="always"> to prevent overflowing the screen on smaller devices.5. Performance & Optimization StrategyTo ensure a smooth 60fps experience while monitoring 20+ camera feeds and receiving real-time WebSocket data:1. State Batching (Anti-DDoS)Rule: Never trigger global REST API invalidations (e.g., queryClient.invalidateQueries()) directly inside a WebSocket onmessage handler.Implementation: Update React state locally first. If an API refetch is absolutely necessary, wrap it in a debouncer or setTimeout(..., 0) to let the React render cycle complete before thrashing the network.2. DOM Node PreservationWhen rendering camera grids, use stable React key props tied to the database camera.id, not array indices. This prevents the browser from tearing down and rebuilding heavy <video> or WebRTC elements when the list order changes.3. Rendering ThrottlingTimestamps (e.g., "Just now", "2 mins ago") should be calculated in a pure formatting function (like formatTime(value)) rather than running an active setInterval per component, which causes heavy CPU wake-ups.4. Image / Snapshot OptimizationSizing: All thumbnails and AI enrollment crops fetched from the backend must be requested at exact needed dimensions (e.g., ?w=128&h=128), or rely on lightweight Base64 strings.Lazy Loading: Use <img loading="lazy" /> for any historical incident snapshots that appear below the fold in the Incident Feed.6. Responsive breakpoints StrategyVigilZone is mobile-responsive but optimized for Desktop Control Rooms.Mobile (< 640px): Grids collapse to 1 column (grid-cols-1). The Navigation bar collapses into a side <Sheet> menu (Hamburger icon).Tablet (md: 768px): Grids expand to 2 columns. Sidebars remain hidden or collapsible.Desktop (lg: 1024px): Full dashboard view. Grids expand to 12 columns (e.g., Video Wall col-span-8, Alerts col-span-4).Ultrawide (2xl: 1536px): Camera grids automatically expand to 3 or 4 columns internally (2xl:grid-cols-3) utilizing all available edge-to-edge space.
