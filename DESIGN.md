The Redis stream publisher is in the AI service, not the frontend or the main Django API. broadcast_alert() in services/ai/src/api/server.py calls get_publisher().publish_alert(alert) in services/ai/src/api/server.py, and the real xadd() happens in services/ai/src/services/redis_publisher.py and services/ai/src/services/redis_publisher.py. In the checked-in runtime config, that publisher is enabled by default in docker-compose.yml, so this is live code. The only caveat is that it is intentionally gated by AI_USE_REDIS_PUBLISH; if that env var is off, the publisher is present but disabled by design, not dead.

The consumer side is also real. The backend runs a long-lived Redis stream subscriber in services/backend/ai_integration/management/commands/subscribe_incidents.py, and docker-compose starts it as incident_subscriber in docker-compose.yml with the command in docker-compose.yml. That command reads stream entries and hands them to process_alert_event() in services/backend/ai_integration/management/commands/subscribe_incidents.py and services/backend/ai_integration/incident_ingest.py. From there, incident_ingest.py queues the live notification dispatch on commit in services/backend/ai_integration/incident_ingest.py and services/backend/ai_integration/incident_ingest.py, which calls NotificationService.broadcast_incident().

What actually pushes incidents to the frontend is not Redis streams. It is Django Channels WebSocket fan-out from NotificationService, specifically services/backend/api/notification_service.py and its channel broadcast path in services/backend/api/notification_service.py. The WebSocket consumer is services/backend/api/consumers.py for group subscription and services/backend/api/consumers.py for the inbound notification handler that sends JSON to the browser. On the frontend, the live consumer is useNotifications() in web/ui/client/src/hooks/useNotifications.ts, which opens the WebSocket, handles messages in web/ui/client/src/hooks/useNotifications.ts, updates unread state, and invalidates incident queries in web/ui/client/src/hooks/useNotifications.ts. NavBar is the component actually consuming that hook in web/ui/client/src/components/NavBar.tsx and web/ui/client/src/components/NavBar.tsx.
